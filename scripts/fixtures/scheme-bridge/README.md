# OpenLR local frontend scheme bridge candidate

Diagnostic source prototype only. It is not adopted by OpenLR and does not claim general MyGo replacement compatibility. The build copies the selected, unmodified `github.com/egoist/mygo v0.7.4` into private staging, applies the exact patch, builds the independent fixture, and removes that copied module. The upstream module cache and project module files are unchanged. Patch context and modified upstream files derive from MyGo v0.7.4, copyright 2026 MyGo contributors, under the existing [MIT notice](../../../resources/licenses/mygo-MIT.txt).

On actual macOS:

```sh
node scripts/build-scheme-bridge-probe.mjs build/scheme-bridge-probe
node scripts/run-scheme-bridge-probe.mjs build/scheme-bridge-probe
```

The executable, selected build information, JSON assertions, native logs, and owned-process exit record remain under that output directory. The runner has a 90 second deadline and kills only its newly created process group on timeout. It does not claim ownership or cleanup of WebKit helpers launched through launchd. Use a fresh output directory for another run; log creation deliberately rejects overwriting prior evidence. A cross-compilation check can set `GOOS=darwin GOARCH=arm64` and run the builder on another OS; that does not execute or validate WKWebView.

## Candidate mechanism

Darwin registers no WK script message handlers. A top-frame-only injected bridge closure sends the original secret-prefixed JSON to a reserved `mygo://localhost/__openlr_bridge` POST endpoint. The native scheme handler reserves this path before any application protocol handler, associates the task with its actual WKWebView, validates the current local-page capability, and calls the original `w.h.Message` / `Window.handleMessage`. The core's secret check, bound-call routing, untrusted limits, page context, and outbound dispatcher stay in one place. No trusted payload size ceiling is added. The adapter retains MyGo's existing full request-body copying; this prototype does not claim streaming or reduced peak memory.

The renderer serializes request admission, and native sequence validation detects reordered/duplicate admission. An ACK means the dispatcher accepted the message, not that a bound method finished. Waiting for bound-method completion would deadlock channel backpressure. Any fetch failure stops admission for that document: a possibly executed call is never replayed, and later calls reject visibly instead of sending uncertain sequence numbers. Fetch failure settles a pending bound call with a visible error; non-call transport failures surface as renderer errors.

A provisional navigation prepares a fresh capability only for future document-start scripts. The still-live document retains its active capability until commit. Commit promotes the next capability and cancels pending native Eval records; provisional failure discards the pending capability. Pending state is keyed by the public WKNavigation identity: a late failure from a superseded navigation cannot discard the current pending capability; an unmatched commit fails closed. This relies on public WKUserScript replacement reaching the new document before injection and must be checked on target WebKit. The fixture tests same-document navigation, prevented navigation, an actual TCP provisional load failure, successful navigation, old-page call cancellation, and replay of an old capability after commit.

Result-bearing `Page.Eval` still uses native `callAsyncJavaScript` with **nil arguments**, so native compilation and MyGo's existing expression-to-statement SyntaxError fallback remain. The wrapped body executes once; its result string returns through a unique scheme reply. The body then returns an intentionally uncloneable function. Only the exact public `WKErrorDomain` / `WKErrorJavaScriptResultTypeIsUnsupported` (5), combined with an admitted matching reply in the same document, completes successfully. Missing/duplicate replies and every other native error remain errors. A per-record completion guard prevents a later native callback from completing a canceled request twice. Transport errors are prefixed with `OpenLR scheme transport`, so a transport `SyntaxError` after execution cannot trigger MyGo's compile-error fallback and execute user code again. No `eval` or `Function` constructor is introduced.

This unsupported-result completion is an experimental protocol and requires actual target WebKit evidence. A normally returned supported result would reenter the original deserialization branch; the candidate reports that as a failure, not a fallback. Existing fire-and-forget native Eval retains its nil completion handler.

## Boundaries and remaining gaps

- This prototype supports the local `mygo://localhost` frontend without restrictive CSP. Remote and other-scheme pages fail closed. Fetch is subject to `connect-src`; therefore this does **not** preserve MyGo's documented general CSP-independent `Page.Eval` contract. Native compilation remains native, but its new reply transport has that additional restriction.
- Public `WKURLSchemeTask` exposes no `WKFrameInfo.isMainFrame`. Top-frame-only capability injection, exact task-owning WKWebView, and current-document rotation are narrower checks, not proof of native frame identity. The fixture checks an ordinary same-origin child gets no injected bridge and rejects a forged capability. It does not establish security against hostile same-origin top-frame script, injected preload code, capability exfiltration, or general `PageOptions.Untrusted`/remote-page usage. Those framework boundaries remain unresolved; no production or general framework claim is made.
- Back/forward-cache restoration is explicitly unsupported: a persisted `pageshow` stops the old document's transport and raises a visible diagnostic error. Its aborted controller and old capability are never silently reused. Redirects with multiple provisional navigations, window.open, process replacement, file drops with actual native file objects, and actual picture-in-picture transitions are not validated by this fixture. PiP state messages use the same capability-checked scheme endpoint; the fixture confirms neither former script-message handler is installed. Features and GC are not disabled.
- Core context cancellation retains the existing meaning: stop waiting; it does not cancel JavaScript execution. An optional `CallAsyncFunctionContext` adapter removes the candidate's native pending-map ownership on cancellation, on the existing backend main queue, without changing other platforms or duplicating the core evaluation rule. A completion guard handles later callbacks exactly once. WebKit may still retain its completion block and already-running or unresolved JavaScript continuation; the public API offers no cancellation for that work. The fixture checks a late canceled reply cannot complete a subsequent Eval. Pending map records are also removed on completion, navigation commit, or window/web-view close.
- A functional fixture pass does not establish that all possible host JSC context creators have been eliminated or that the original application trap is fixed. Application verification is a separate experiment.

## Evidence and sources

Source inspection supports the branch selection, independently of the still-pending native candidate run:

- [Pinned WebKit WKUserContentController.mm](https://github.com/apple-oss-distributions/WebKit/blob/e97539821b38379d82a51b6740d90191d5d0b7af/Source/WebKit/UIProcess/API/Cocoa/WKUserContentController.mm#L149) deserializes script-message bodies before calling the delegate (lines 149–185).
- [Pinned WebKit WKWebView.mm](https://github.com/apple-oss-distributions/WebKit/blob/e97539821b38379d82a51b6740d90191d5d0b7af/Source/WebKit/UIProcess/API/Cocoa/WKWebView.mm#L1265) returns early for a nil completion handler, sends errors without successful-result deserialization, and handles an unsupported result before the success deserializer (lines 1265–1322).
- [Apple WKURLSchemeTask](https://developer.apple.com/documentation/webkit/wkurlschemetask), [callAsyncJavaScript](https://developer.apple.com/documentation/webkit/wkwebview/callasyncjavascript(_:arguments:in:in:completionhandler:)), and [unsupported result status](https://developer.apple.com/documentation/webkit/wkerror/code/javascriptresulttypeisunsupported?language=objc) define the public interfaces used here.
- [MyGo v0.8.3 Darwin window.go](https://github.com/egoist/mygo/blob/v0.8.3/internal/darwin/window.go#L1696) retains result-bearing CallAsyncFunction and script-message delivery (handler around line 2465). There is no source evidence that upgrading alone repairs these paths.
- MyGo threading and custom-protocol guidance was also consulted through Context7 `/egoist/mygo`; protocol responders remain on the main thread and bound-call work retains its existing dispatch. Context7 guidance is explanatory, while the pinned source and native fixture determine the actual candidate behavior.

The independent prior public-JSC stack fixture demonstrated Go-stack exposure versus native stack bounds. Its result motivates this transport experiment; it is not evidence that this candidate already works. Update conclusions only from retained native reports and logs.
