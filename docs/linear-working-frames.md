# Linear working-frame kernel

Choose **Processing → Linear** in the detail editor, or run `processing --version 2`, to use the float pipeline for a still photo. **Original** (`--version 1`) retains the byte pipeline. Existing photos and ordinary new imports keep their current/default legacy processing unless explicitly switched; an imported OpenLR XMP recipe carries its own version. The GUI and CLI use the same dispatcher. Video remains on original processing.

## Boundaries

`decodePhotoFrame(file)` returns an owned straight-alpha RGBA Float32 frame in signed, unbounded linear sRGB. RAW uses actual 16-bit wide LibRaw output. PNG, TIFF and supported SDR AVIF interpret native integer samples directly; JPEG XL uses native FLOAT output and its actual DATA color profile. These paths avoid a bitmap/canvas bridge before the working frame. The distinct `decodePhotoLinear` contract used by DNG/HDR remains linear sRGB. Worker execution and startup compatibility use the same decoder and input transform.

| Input | Linear processing source contract |
| --- | --- |
| Camera RAW/DNG | Existing wide LibRaw 16-bit decode and its recorded matrix/precision provenance |
| Classic TIFF | First image; unsigned chunky RGB/RGBA or WhiteIsZero/BlackIsZero grayscale with optional alpha; 8/16-bit samples, with packed 1/2/4-bit samples supported by the normalized adapter; 8-bit palette indices retain the color map's 16-bit RGB entries. Both byte orders, strips/tiles, uncompressed/LZW/Deflate/PackBits, predictors 1/2 and orientations 1–8 use the shared UTIF decoder |
| AVIF | Actual 8/10/12-bit source decoded through existing libavif to integer RGBA16, then normalized by 65535. Provenance keeps the actual source depth; 16-bit transport does not imply a 16-bit source |
| PNG | Defined grayscale/RGB/palette/alpha layouts, packed 1/2/4-bit and 8/16-bit samples, filters 0–4 and Adam7. Numeric reconstruction retains full-depth transparency keys and straight alpha; APNG supplies the first animation frame, matching the existing still-photo display |
| JPEG XL | Shared pinned libjxl decoder, native FLOAT transport from integer or floating sources, actual DATA ICC through its existing skcms into linear sRGB; first coalesced display frame and codestream orientation |
| JPEG and display compatibility | Existing display decoder followed by an RGBA8-to-linear conversion; provenance explicitly says `rgba8-display` |

TIFF unsigned RGB/palette input can use the embedded RGB matrix/TRC profile subset described in [color handling](export-color.md#input-color-and-re-import); unprofiled RGB and grayscale use the existing sRGB assumption. Alpha is normalized separately, associated alpha is undone before color conversion, and straight hidden RGB is retained. FillOrder defaults to 1. FillOrder 2 is supported for one-channel bilevel uncompressed or existing CCITT Group 3/4 decoding; ambiguous combinations with other depths/compressions and invalid order values fail visibly. Uncompressed LSB-first bytes are normalized once in the shared reader; CCITT's own bit reader already honors the order. Predictor 1 is supported; predictor 2 requires 8/16-bit samples. Other predictors, floating/signed TIFF, separate planes, unsupported layouts and sensor TIFF/DNG fail visibly; `.dng` continues through LibRaw. Generic CMYK uses the existing display compatibility route. Decoder bounds and malformed compressed data fail rather than manufacturing missing black samples. TIFF import remains classic TIFF only; arbitrary TIFF encodings and very large allocations need further coverage.

AVIF embedded ICC takes precedence over CICP RGB characterization. Without ICC, primaries 1/2 with transfer 13/2 use the existing sRGB assumption; primaries 12 with transfer 13 use Display P3. Unspecified code 2 is an assumption, not measured source colorimetry. Other CICP transfers/primaries, including PQ/HLG, use the existing host display decoder when available. Structurally valid RGB ICC outside the supported matrix/TRC subset uses the existing host CMS compatibility route. These routes retain `rgba8-display` plus a `compatibilityReason`; malformed ICC or an unavailable host decoder fails visibly. Compatibility is not high-depth HDR or general ICC support.

PNG characterization follows its own precedence: cICP, iCCP, sRGB, then gAMA/cHRM. RGB matrix/TRC and gray kTRC XYZ-PCS profiles share the existing ICC interpreter; gamma/chromaticities reuse the color-space matrix and Bradford adaptation owner. The inverse of PNG encoding gamma is the decoding exponent; gAMA 45455 is not exact sRGB. Missing characterization is a recorded sRGB assumption. Unsupported profiles or cICP use explicit display compatibility. Full-range cICP sRGB and Display P3 with transfer 13 are interpreted directly; other transfers, including HDR, remain compatibility. EXIF orientation uses the same pixel mapping as TIFF. Color warnings and significant-bit metadata remain in provenance; damaged palette entries follow the specified opaque-black recovery with an Info diagnostic. See [PNG input decision](decisions/010-png-working-input.md), [sample experiments](../research/high-depth-png.md), and [input color evidence](../research/png-input-color.md).

JPEG XL retains source bit depth and exponent bits separately from its Float32 output. The existing bundled skcms handles supported RGB/gray matrix/TRC and in-range table profiles; its A2B selection prefers A2B0 then A2B1, rather than promising a selectable rendering intent. Signed analytic profiles preserve negative values and highlights. The working adapter corrects measured XYZ PCS scaling in pinned skcms mAB/mft2; XYZ mft1 uses `jxl-profile-unsupported` because its 8-bit PCSXYZ interpretation is not standardized. Structured PQ/HLG uses `jxl-hdr-transfer` compatibility; out-of-range native RGB with sampled curves or A2B uses `jxl-profile-range`. These cases convert the same decoded samples to the established display result, without another decompression. Libjxl already applies orientation and unpremultiplies alpha; Linear conversion uses straight alpha. Original processing retains the published byte decoder policy, including its associated-alpha behavior, for existing recipe compatibility. See [JPEG XL input decision](decisions/011-jxl-working-input.md) and [color evidence](../research/jxl-input-color.md). The pinned encoder/decoder pair has a reproducible small-width FLOAT roundtrip defect documented there; the experiment does not identify which side causes it. Tested native precision is not a claim of lossless behavior for every JPEG XL source.

The detail Info text reports actual decoded precision or **8-bit compatibility decode**. Full and summary `state` expose `processing:{version,input}`; `input` is the current asset/version's decoder provenance, including precision, source/output depth and color transform or compatibility reason when available. It is `null` while no matching decoded source is cached. A Float32 frame, a filename extension or a TIFF16 export alone does not establish retained source precision. The [input decoding decision](decisions/009-high-depth-input.md) records this boundary and alternatives.

`renderFrame(frame, edit, maxSize)` copies source samples before edits. Stage order is fill, red-eye, repairs, depth blur, local masks, optics/TCA, crop/turn/flip/resize, global tone, curve, HSL/point color, then spatial effects. Originals are never mutated. Stage modules own the same rules used by the legacy adapter:

- Local and global exposure/contrast/saturation and repair blending operate in linear light. Healing adds an unclipped mean residual; each repair samples an immutable pre-stroke state. Range masks share a pre-blur/pre-mask reference.
- Color selection uses continuous signed encoded sRGB against existing hex swatches. Luminance selection uses linear RGB directly. Global tonal influence is bounded to [0,1], while RGB remains unbounded.
- Curves interpolate existing encoded-domain control stops continuously and extend as identity outside [0,1]. HSL maps signed/HDR samples into an affine envelope and restores that envelope after adjustment; unmatched colors remain unchanged.
- Optional [point curves](tone-curves.md) follow the old curve stage: RGB master, then individual channel, in continuous signed encoded sRGB. Editable endpoint output uses unit-slope offset tails outside [0,1], preserving exterior variation without clipping. The old three-slider curve and its identity tails remain unchanged.
- Geometry uses alpha-weighted linear bilinear sampling. Resize clamps edge coordinates; optics uses a transparent exterior and conservative TCA alpha. Integer crops, quarter turns and reflections copy samples exactly.
- Existing fill patches retain their honest RGBA8 precision: only patch pixels are decoded and composed into the float base. Red-eye changes corrected red through the continuous encoded-domain rule without quantizing other channels.
- Spatial effects retain alpha and ignore invisible neighbor colors. Defocus uses normalized premultiplied convolution, spreading coverage with the blur; focused samples remain exact.

`frameCanvas` is a terminal sRGB display adapter. `encodeFrameTiff` converts the float result directly to target-space Uint16 samples, then uses the existing worker and TIFF writer with a matching ICC. Both output adapters clip only at their representable output boundary. Source values clipped earlier inside LibRaw cannot be reconstructed. Watermarks rasterize only their text/shadow layer and alpha-compose it into the linear result. PNG, JPEG, AVIF and JPEG XL convert directly from the float result into the requested target space before terminal 8-bit quantization; they do not pass through an sRGB preview. JPEG composites transparency over black in linear light. High-depth output beyond TIFF remains unimplemented.

## Verification

```sh
node --test tests/float-color.test.js tests/float-local.test.js tests/float-geometry.test.js tests/float-render.test.js tests/float-tiff.test.js tests/float-raw.test.js tests/float-mask-preview.test.js

node --test tests/png-layout.test.js tests/png-color.test.js tests/png-input.test.js tests/png-workflow.test.js
node --test tests/process-version-transport.test.js tests/process-version-workflow.test.js tests/sync.test.js tests/local.test.js
node --test tests/tiff-layout.test.js tests/tiff-input.test.js tests/avif-depth.test.js tests/avif-input.test.js tests/icc-input.test.js tests/high-depth-workflow.test.js
npm test
```

Numerical tests cover negative values, highlights, sub-byte differences, alpha coverage, immutable sources and captured legacy results. The shared renderer retains all 256 gray levels through local +4 EV followed by global −4 EV. TIFF tests independently decode true 16-bit low samples and verify strip byte counts, sliced arrays, large ICC offsets and exact legacy encoding. Browser RAW tests use generated sensor DNGs and actual WASM, including worker/fallback equivalence, wide-color reconstruction, orientation, failure recovery and source preservation. Their generated fixtures are evidence of these numerical cases, not proof of all camera formats or full application migration.

High-depth input checks cover generated TIFF16 and AVIF10/12 low codes, float profile conversion, alpha/orientation, normal-worker and forced startup-fallback equivalence, source immutability, visible compatibility, malformed input and genuine TIFF16 export/re-import. Independent native Little CMS comparisons validate the supported source-profile interpreter separately from codec behavior. Reproduction, measured tolerances and limitations belong to [TIFF research](../research/high-depth-tiff.md), [AVIF research](../research/high-depth-avif.md) and [ICC research](../research/float-input-color.md). The commands above are verification entry points; platform acceptance requires the actual run recorded in [acceptance](acceptance.md).

Browser workflow tests verify explicit upgrade, undo/redo/reset, version-preserving comparisons, named versions, presets, XMP including depth settings, reopening, true TIFF16 output and unchanged legacy pixels. Original source caches include processing version; recipe changes decode for the requested version before writing thumbnails. Model analysis receives a separate display surface associated with the owned float source. Range overlays select at original resolution using the same immutable float fill/red-eye/repair reference as adjustments, then downsample coverage; resampling source colors first could invent a selected color. Commands serialize source changes with the active recipe; slider preview additionally checks recipe identity and cache processing version. Sync and library changes invalidate source caches.

Local sidecars and sync manifests use their existing format-version rejection mechanism to protect new recipes from older clients. Saved linear versions also require the newer envelope even when current processing is original. Concurrent recipe-version transitions are atomic sync conflicts. See [versioning decision](decisions/008-processing-version.md), [local folders](local-folders.md) and [sync](library-sync.md).

The native smoke suite exercises actual RAW opt-in, CLI TIFF16 low-bit inspection, reset and switching back. The native local suite verifies sidecar persistence, saved versions, restart and rejection of unsupported recipes. Each platform must pass its own run; browser tests alone do not establish native acceptance.
