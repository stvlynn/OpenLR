# Native audio export bridge design

The current video-container export owns one `Input`, one `Output`, a trim range and the edited frame callback. Its existing MediaBunny conversion runs unchanged where the required exact configurations are available. The macOS desktop fallback replaces specific audio tracks within that export when exact browser codecs are unavailable. It shares the original file and requested trim with the video conversion. The preview element and its clock never supply export samples or timestamps. [Video export](../web/video.js) · [Desktop CLI contract](../docs/agent-cli.md)

## Per-export ownership

1. Enumerate tracks with their decoder configuration, rate, channel count, language, disposition and pairability before starting output. Choose decode and encode capability separately. When the normal conversion cannot preserve an audio configuration, substitute an explicitly planned native track. A missing exact capability produces a track-specific error. Codec support for the same channel count and sample rate is a requirement of this fallback. A cross-codec rate change would need an explicitly chosen resampling path and an exact destination sample count. It must preserve the channels and report unsupported configurations visibly.
2. Use `Conversion.init({ composable: true, copy: false, trim, … })` for the edited video and other supported tracks on the fallback branch. `copy: false` keeps `_timestampOffset` anchored to `-trim.start` instead of allowing packet-copy expansion to shift the common output timeline. Set `audio(track)` to discard only tracks that have a matching explicit `EncodedAudioPacketSource`, and reconcile `utilizedTracks` plus planned replacements with every input track before starting the output. Preserve input name, language, disposition, metadata tags and track groups when constructing the replacement. A track with no audible overlap needs an explicit product policy if the output container cannot represent it as empty.
3. Bind bounded native codec streams to one export and the originating native window. The bridge opens a converter with codec, direction, exact sample rate and channel count, verified codec description and optional frames per packet. It returns an opaque stream ID and negotiated configuration. Each process call carries at most 64 KiB of packed coded data or interleaved little-endian Float32 PCM. Decode input includes packet offsets, sizes and coded frame counts. A reply returns owned bytes, packet descriptions for encoded output, produced frames, consumed frames and terminal or needs-input flags. Submit the next chunk only after `NeedInput`. Finalize by passing EOF and pulling until `Done`. Read encoder prime and output description before closing. A stream from another native window or an ended export cannot be reused.
4. Drive the audio tracks and composable conversion in shared timestamp windows using `conversion.execute({ until })`, so one producer cannot queue an entire track while another starts later. Hold the first packet until the encoder's priming and description are known. Retain the tail until total coded and audible counts establish its discard. WebM's final block can represent only the padding in that block. If whole trailing packets contain only padding, omit them once the coded boundary is known. On failure or abort, close each stream, cancel unfinished conversion and output work, and dispose the shared input while retaining the primary error. Save the export only after output finalization and track reconciliation. Keep user data out of diagnostics. [Native stream protocol](../internal/nativeaudio/stream.go) · [MediaBunny composable conversion](https://github.com/Vanilagy/mediabunny/blob/v1.65.1/src/conversion.ts)

## Sample clock and prerequisites

`web/audio-timing.js` intersects requested and intrinsic presentation ranges on an integer sample clock. It rounds each shared boundary once, so adjacent trims meet on the same sample. A delayed track keeps its positive offset from trim zero. The encoded first packet starts at audible start minus the measured encoder prime. Later packet times advance by cumulative coded samples. The final discard is the completed coded count minus leading prime and submitted audible frames. The MP4 movie timescale is the least common multiple of the chosen sample rates and MediaBunny's existing 57,600 ticks per second, bounded by the unsigned 32-bit container field. For Opus WebM the proven explicit mode uses 10 µs timestamp ticks. [Timing patch and independent verification](audio-container-timing.md)

The decode adapter needs the coded frame position represented by the first returned PCM frame. `ConsumedFrames` measures input consumption and `Frames` measures raw output. Together they do not say whether a short output is buffering, a leading omission, or tail behavior. Both tested macOS architectures omitted the first 120 samples of the tested CELT-only Opus sequence, even with different cookies. No fixed 120-frame correction follows for SILK, hybrid, mixed modes or a newly opened seek decoder. The leading sample position must come from a verified decoder contract. A raw reference Opus decoder that returns each TOC-defined frame count can avoid this ambiguity. The selected libopus adapter now has independent mixed-mode and preroll evidence in [the decoder record](native-audio-origin.md). Packaged macOS execution still requires verification. [Observed AudioToolbox behavior](native-video.md) · [Opus packet structure](https://www.rfc-editor.org/rfc/rfc6716.html#section-3)

For an interior decode, use the previous key packet at least the track's declared preroll before the requested start and retain its actual coded timestamp. Apply Opus pre-skip as a stream-origin presentation bound. When starting later, it does not become new codec priming. Apply MP4's finite intrinsic edit and signed WebM discard on the original coded timeline, once. Preserve actual gaps. Distinguish container tick quantization from genuine discontinuities before advancing the integer PCM clock. The source patch exposes a laced block's padding on the expanded boundary packet. If the discard extends across several lace packets, the caller must resolve its block span before emitting affected samples or fail visibly. A large decode counter or a rounded packet timestamp is insufficient to reconstruct omitted source audio.

The native converter currently returns an opaque AudioToolbox cookie. Verify its AAC `DecoderSpecificInfo` before constructing a muxer `AudioSpecificConfig`, and exercise the corresponding decoder cookie path on both macOS architectures. The earlier Chrome packet probe built an AAC-LC configuration from its known fixture rates and channel count. It does not establish support for every incoming AAC profile or channel layout. For Opus output, build and verify an `OpusHead` consistent with the negotiated rate, channel mapping and measured priming before using it as the muxer's decoder description. The Go stream package currently accepts one or two channels. A fallback unable to preserve a source layout must fail without falling through to MediaBunny's default downmix. [AudioToolbox packet evidence](native-video.md) · [Opus identification header](https://www.rfc-editor.org/rfc/rfc7845.html#section-5.1)

Before declaring this branch accepted, verify a real macOS export containing edited video and independently recognizable audio in both output containers. Cover a non-packet-aligned interior cut, delayed and multiple audio tracks, AAC 44.1/48 kHz and Opus, independent PCM content at both edges, and a failed capability or canceled export with closed native streams. `node --test tests/audio-timing.test.js` verifies the clock math in isolation. Those helper tests do not exercise native decoding or select a codec backend.

## Implemented boundary and current verification

`web/native-audio.js` now owns the bounded renderer transport, `web/audio-track.js` the source sample clock and presentation intersection, and `web/audio-export.js` the replacement packet sources and composable conversion. The ordinary browser conversion remains selected when exact decoding and encoding are available. The macOS branch uses the existing MyGo platform value and the window-owned `NativeAudio` binding. Track gaps become bounded silence when producing a continuous encoded track; delayed first samples retain their positive offset. A replaced track with no audible overlap fails visibly before output starts.

The demuxer exposes the original lace anchor and member indices so signed block discard can cover several decoded packets. Its existing preroll API also respects a longer declared Matroska SeekPreRoll. Coarse source timestamps use integer coded duration and a source-tick residual range, with a packet-header scan before an interior seek; decode still begins at actual preroll. This preserves phase without treating every rounded packet timestamp as a new clock origin.

Actual Chrome integration with an injected encoder covers two audio tracks, a delayed stereo start, a genuine gap, an unaligned trim across several conversion windows, exact independently decoded sample counts and channel signal, track metadata and pairability, edited video pixels, unchanged source bytes and cancellation. Additional real Opus fixtures and MP4-container tests cover lace discard and the AAC timing interface; AAC decoding in that timeline test is injected. These do not prove actual renderer-to-AudioToolbox export. The independent native AAC input probe and packaged macOS video workflow are the next required checks.
