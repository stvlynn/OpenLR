## Core editing gaps found in current source

1. **Point and channel tone curves.** `web/adjustments.js` defines only three fixed quarter-stop sliders. `web/color.js` constructs five stops with fixed black/white endpoints, and the renderer applies the same scalar curve to all channels. There is no arbitrary point owner, channel selector or point-editing command. This prevents independent channel shaping and freely positioned knots; it is more than a missing label. The next implementation will add an independent point-curve owner and GUI/CLI workflow while preserving existing recipes and their three-slider rendering. Research, interpolation alternatives and numerical experiments belong in [point tone curves](point-tone-curves.md).
2. **Tonal color grading.** Existing HSL mixing selects color ranges; it does not provide independently controlled shadow/midtone/highlight/global grading. The Lightroom L1 records contain corresponding entries, but these do not establish Adobe's formulas. An independent implementation needs a declared luminance weighting model, research and pixel tests rather than renaming HSL controls.
3. **Dehaze.** Effects currently contain Texture, Clarity, Vignette and Grain. The L1 ledger includes a dehaze parameter, but the application has no such control, command or processing stage. Clarity is not evidence that haze removal is implemented. Algorithm choice and ablation remain work to do.

Competitor observations are factual inputs, not automatic product requirements. The user's requested reconstruction and the existing broad editing scope motivate investigating these gaps; implementation contracts must explicitly define OpenLR's independent behavior. No Adobe code, assets, calibration data or proprietary algorithms are imported by this audit.
