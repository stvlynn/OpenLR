# Native video verification

The 2026-11-06 [native video smoke](../scripts/native-video-smoke.mjs) generates a three-second VP9/Opus WebM. Its consecutive one-second segments pair red, green, and blue frames with 330, 660, and 990 Hz tones. The real desktop CLI imports the clip, seeks, advances playback, pauses, trims to 1.2–2.7 seconds, rotates the frames, and writes previews, a saved catalog frame, and the trimmed WebM. A separate Chrome page uses the bundled MediaBunny sinks and Chrome's decoders to inspect the written files. It checks the saved PNG against the paused preview and samples two frames and two windows of decoded PCM in the trim. The test also checks that the exports preserve the selected asset, paused playback, and catalog edit, and that exporting the original returns the same bytes as the source fixture.

| Local execution                                                                   | Play → advanced → paused, seconds | WebM container / decoded PCM, seconds | 660 / 990 Hz amplitude | Original bytes |
| --------------------------------------------------------------------------------- | --------------------------------- | ------------------------------------- | ---------------------- | -------------- |
| Windows WebView2, packaged `build/organization-state/windows-amd64/OpenLR.exe`    | 0.350 → 0.544285 → 0.548517       | 1.513 / 1.5135                        | 0.19974 / 0.20005      | 27,479         |
| WSL Ubuntu 24.04, WebKitGTK 2.52.6, Xvfb and D-Bus, with the VP9 parser available | 0.350 → 0.565917 → 0.582758       | 1.500 / 1.4935                        | 0.20009 / 0.20017      | 27,487         |

Both runs used Node 24.9.0 and produced a 64×96 saved still and a 64×96 VP9/Opus WebM. The saved still matched the blue preview sample. The exported green and blue segments had the expected tones, and both decoded audio windows had RMS near 0.141. The audio evidence comes from the exported PCM samples. Physical audio output remains unverified for this workflow. The ignored log for the final Windows run is `.workspace/native-video-windows.log`.

## Linux VP9 parser

The Linux runtime probe used the pre-existing executable under `openlr-acceptance-8ec94b8/build/release/linux-amd64/openlr`. The archive directory is a provenance label. It has no Git metadata, and its copy of `web/video.js` matched the current source byte for byte. The host used Ubuntu's `libwebkit2gtk-4.1-0` 2.52.6-0ubuntu0.24.04.1 with `gstreamer1.0-plugins-good` 1.24.2-1ubuntu1.8. The Chrome fixture and decoder used version 157.0.8103.38.

1. With the installed GStreamer plugins, import, seek, time advance, pause, trim, and the rotated preview reached their assertions. Export failed with `This device cannot encode every source track in the selected video format`. WebKit stderr identified the missing `vp9parse` element. The command stopped at export.
2. Both Ubuntu packages, `gstreamer1.0-plugins-bad` and `libgstreamer-plugins-bad1.0-0` at version 1.24.2-1ubuntu4, were unpacked into temporary storage. `GST_PLUGIN_PATH_1_0` exposed only `libgstvideoparsersbad.so`, `LD_LIBRARY_PATH` supplied its codec parser library, and `GST_REGISTRY_1_0` selected a private registry. The system packages stayed as installed. [Ubuntu parser package](https://packages.ubuntu.com/noble/gstreamer1.0-plugins-bad) · [Ubuntu package file list](https://packages.ubuntu.com/noble/amd64/gstreamer1.0-plugins-bad/filelist)
3. With the same executable and smoke, the test passed through export, independent frame and audio decoding, original bytes, and save-frame. WebKit still reported missing WebVTT encoding and `autovideoflip` in this selective extraction. The paired observations are retained in the ignored `.workspace/native-video-linux-missing-parser.log` and `.workspace/native-video-linux-provisioned.log`.

The missing parser was the export blocker in this environment. CI now installs `gstreamer1.0-plugins-bad`, and the Linux package manifest declares the base, good, and bad sets for Opus, VP9, and the parser. See the [desktop runtime requirements](../docs/desktop.md).

## macOS import failure

The Intel job on macOS 15.7.9 (24G830) for application commit `7dc0d11` passed Go test and vet, built the universal package, and completed the main, organization, mask, and navigation smoke workflows. The native video smoke generated its fixture and then failed at the first video import assertion. The failed-file entry for `clip.webm` said `The operation is insecure.` The test never reached seek, playback, save-frame, or export. The exact job log is retained in `.workspace/preview-consistency-ci-macos.log`. [Actions job 127542080186](https://github.com/stvlynn/OpenLR/actions/runs/42112118876/job/127542080186)

The import result at that revision kept only the exception message. The job could not distinguish media loading, poster capture, thumbnail rendering or encoding, and catalog persistence. Source inspection found that MyGo v0.7.4 loads the packaged frontend from `mygo://localhost/` via `WKURLSchemeHandler`, and OpenLR uses a same-document Blob URL for the imported file. Current upstream WebKit's video-to-ImageBitmap path can resolve with a bitmap whose origin-clean flag is false. Later canvas serialization can throw a security exception on such a bitmap. That makes the origin handling a hypothesis for this failure. An older WebKit issue records a similar security exception from a Blob-backed WKWebView video through WebGL, which is a different operation. [MyGo frontend URL](https://github.com/egoist/mygo/blob/v0.7.4/frontend.go) · [MyGo WKWebView setup](https://github.com/egoist/mygo/blob/v0.7.4/internal/darwin/window.go) · [WebKit ImageBitmap source](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/html/ImageBitmap.cpp) · [WebKit canvas serialization source](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/html/HTMLCanvasElement.cpp) · [WebKit issue 186353](https://bugs.webkit.org/show_bug.cgi?id=186353)

The CLI separately had no mappings for the five video suffixes recognized by the app, so the failed job handed the renderer `application/octet-stream` for the WebM. The CLI now sends `video/webm` for WebM, `video/quicktime` for MOV, `video/mp4` for MP4 and M4V, and `video/matroska` for MKV. The authenticated transport test checks the declarations and unchanged file bytes. The effect of the type on the macOS failure remains unverified. [IANA media type registry](https://www.iana.org/assignments/media-types/media-types.xhtml)

The native suite already launches with `OPENLR_DIAGNOSTICS=1`. On video import failure that opt-in now reports the operation stage, exception class, document and Blob origin categories, secure-context and codec API availability, and available media readiness, dimensions, and error code. Import returns its original failed-file response independently of diagnostic delivery. The emitted diagnostic omits filenames, URLs, source bytes and exception messages. A Chrome test uses controlled poster bitmap and thumbnail encoding failures to check the stages, opt-in gate and behavior when the diagnostic bridge throws, rejects or never replies. A macOS run with the diagnostic still needs to locate the failure in the actual host.

The rebuilt Windows executable at `build/retouch-order/windows-amd64/OpenLR.exe` exercised the real diagnostic bridge with a generated, truncated EBML header. The CLI returned `PipelineStatus::DEMUXER_ERROR_COULD_NOT_OPEN: FFmpegDemuxer: open context failed`, left the catalog empty, then imported a valid 2×2 PNG and exported its original bytes unchanged. The one stderr diagnostic reported `media-load`, exception class `Error`, declared video type, ready state 0, network state 3, media error code 4, and dimensions 0×0. It classified the document origin as a tuple and the Blob origin as same, with a secure context and no literal `mygo:` page scheme. All four WebCodecs availability flags were true. The diagnostic contained no filename, path, token, or original error message. The ignored log is `.workspace/retouch-order-video-diagnostic.log`. This exercises Windows media-load diagnostics with invalid input. The macOS failure involved a generated playable fixture and still needs a stage report from that host.
