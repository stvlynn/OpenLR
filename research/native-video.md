# Native video verification

The 2026-11-06 [native video smoke](../scripts/native-video-smoke.mjs) generates a three-second VP9/Opus WebM. Its consecutive one-second segments pair red, green, and blue frames with 330, 660, and 990 Hz tones. The real desktop CLI imports the clip, seeks, advances playback, pauses, trims to 1.2–2.7 seconds, rotates the frames, and writes previews, a saved catalog frame, and the trimmed WebM. A separate Chrome page uses the bundled MediaBunny sinks and Chrome's decoders to inspect the written files. It checks the saved PNG against the paused preview and samples two frames and two windows of decoded PCM in the trim. The test also checks that the exports preserve the selected asset, paused playback, and catalog edit, and that exporting the original returns the same bytes as the source fixture.

### Opus decoder timing ablation

On ARM macOS the pulse offsets were 193 samples in AudioToolbox and 313 in Chrome. The offsets and frame counts are consistent with 120 frames omitted at the head. The first CELT frame's overlap is also 120 samples, which gives a hypothesis for the discrepancy. The existing run did not identify its cause. [Ogg Opus pre-skip](https://www.rfc-editor.org/rfc/rfc7845.html#section-4.2)

WebKit's legacy CoreAudio Opus cookie contains seven big-endian 32-bit words and carries no pre-skip field. Its other path passes `OpusHead`, whose pre-skip is explicit. The ablation prints the generated encoder cookie and decodes the same mono and stereo packet sequences using the encoder cookie with default priming, no cookie, `OpusHead` with pre-skip 0 or 312, and the encoder cookie with `kConverterPrimeMethod_None`. It reports property status, actual priming method, the first output and total PCM frame counts, and the lag and relative RMS error against Chrome in a bounded signal window. Rejected configurations remain visible. These variants require a macOS runner. [WebKit cookie construction](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/platform/graphics/cocoa/WebMAudioUtilitiesCocoa.mm#L344-L371) · [Apple converter priming](https://developer.apple.com/documentation/audiotoolbox/audioconverterprimeinfo)

For a trim, the input timeline needs coded packet positions, container lead and tail discard, and the decoder's output origin. An interior seek requires decoder preroll before the audible start. Apply the track's discard once, then slice PCM at the requested sample boundaries on the shared audio and video timeline. Output metadata must carry the new encoder's priming and the end discard from its final packet. WebM represents these with Opus pre-skip and codec delay plus final-block discard padding. MP4 can use an audio edit list and sample groups to represent AAC timing. Raw round-trip frame counts do not establish container timing.
