# Grid and Filmstrip viewport parity

The Detail viewport shares the browser scroll position between the GUI, the command dispatcher, and `watch`. Grid and Filmstrip are separate scrollports. Before the extension, a person could change which thumbnails were visible without changing the selected photo. The agent could list the catalog and capture its current view. It could not move those thumbnail views or read their offsets. [Viewport contract](../docs/agent-cli.md#shared-session-transport) · [Viewport implementation](../web/viewport.js) · [Prior viewport audit](cli-control-audit.md#confirmed-viewport-gap-and-resolution)

## Observed behavior

On Windows Chrome 156.0.8078.80, a 960×660 workspace loaded 48 generated photos and sorted by filename. Trusted wheel input moved Grid from `y=0` to `640`, changing its visible cards from 00–11 to 12–23. Summary state returned `viewport:null` and the viewport command rejected with “Open a photo in detail view.” The same input moved Filmstrip from `x=0` to `720`, changing its visible cards from 00–06 to 08–14. State and viewport command still returned the independent Detail canvas at `x=0`. Neither native DOM scroll produced an OpenLR change event. Selecting the last photo through the dispatcher left Filmstrip at `x=720` with the selected thumbnail offscreen. The ignored fixture and exact output are `.workspace/catalog-viewport-audit.mjs` and `.workspace/catalog-viewport-audit.log`.

Grid and Filmstrip lay out actual thumbnail elements with browser overflow. `syncTiles` reuses their DOM children when the ordered photo IDs are unchanged and replaces them when the catalog projection changes. Tile image loading is lazy, and Local may independently hydrate source thumbnails. There is no separate virtual scroll coordinate system. Filmstrip is hidden when toggled off, in Grid, and by the slideshow stylesheet. These facts constrain the adapter and the screenshot oracle. ## Command contract

- Extend `viewport` with optional `target: detail | grid | filmstrip`. Omission retains Detail behavior and the existing result shape. Each target resolves at execution to its existing scrollport. Grid requires Grid mode, including an empty view. Filmstrip requires Detail with Filmstrip visible and no slideshow. A hidden target fails without opening it or moving another scrollport.
- Keep `state.viewport` as Detail and add `catalogViewports: {grid, filmstrip}` to full and summary state. Each entry is the actual visible scrollport snapshot or null. A visible empty or fully fitted scrollport reports its dimensions and zero extent. Use the same target resolver for command and state.
- Apply absolute finite, nonnegative CSS-pixel writes with the existing extent clamp and omitted-axis rule. Report the actual browser offset after the move. Reads preserve fractional positions and possible elastic overscroll. Resolve bounds against the current projection after queued scope, filter or sort changes. The existing optional `photoId` still rejects a changed selection; an unguarded request applies to the current view. Preserve existing browser layout and selection behavior, including offscreen selected thumbnails.
- Native element `scroll` triggers the existing workspace-change event for the visible scrollports. Reads and unchanged offsets emit none. The move response and `--capture` continue using the ordered command observer. A capture shows the displayed workspace, including the browser's current thumbnail loading state.

Context7’s MDN references confirmed that CSS scroll offsets can be fractional or temporarily outside normal bounds in Safari, and instant scroll writes are supported. The CSSOM View draft specifies element scroll events for both API writes and user input, with one pending event per element. Use these APIs and existing observations to compare notification behavior. [CSSOM View element scrolling](https://drafts.csswg.org/cssom-view/#dom-element-scrollto) · [CSSOM View scroll events](https://drafts.csswg.org/cssom-view/#scrolling-events) · [MDN scrollTop](https://github.com/mdn/content/blob/main/files/en-us/web/api/element/scrolltop/index.md) · [MDN scrollLeft](https://github.com/mdn/content/blob/main/files/en-us/web/api/element/scrollleft/index.md)

An isolated Chrome run used the existing viewport adapter on the actual Grid element. A move to 200 produced an immediate readback of 200 and one native scroll event. Repeating 200 produced the same readback without an event. Two moves in one task immediately returned 400 and 600, then emitted one native event at 600. Adding the current generic command notification would add one notification per returned command, including the no-op. These results support using the browser event for change observation and keeping the immediate command responses for ordered reads and captures. They do not measure native broker delivery. The ignored experiment is `.workspace/catalog-viewport-events.mjs` and its output is `.workspace/catalog-viewport-events.log`.

Changing the default target to follow the active view would change the existing Grid error and leave Detail ambiguous when Filmstrip is visible. Separate commands would repeat the same bounds and observation contract. The explicit target keeps one dispatcher operation with no additional layout or scroll state. These API comparisons are design reasoning. The trusted-wheel comparison above is runtime evidence.

## Verification

On Windows Chrome 156.0.8078.80, the 48-photo generated catalog displays distinct color bands. The trusted mouse wheel and dispatcher moves produced equal offsets and identical decoded screenshot regions for Grid and Filmstrip. The test checks full and summary state, native scroll notifications, read and no-op quietness, and hidden targets in the opposite view, when Filmstrip is off, and during slideshow. A queued Flagged scope change leaves a single matching photo. The later move clamps against the new zero extent and a guarded command rejects the old selection. The selected photo and edit remain stable during scrolling, and the original export matches the imported bytes.

Run `node --test --test-concurrency=2 tests/catalog-viewport.test.js tests/viewport.test.js tests/panel-state.test.js tests/agent-cli.test.js`. The focused run passed 12/12. Packaged navigation is a separate check through the real CLI, `watch`, and independently decoded native workspace PNGs. [Catalog viewport regression](../tests/catalog-viewport.test.js) · [Native navigation smoke](../scripts/native-navigation-smoke.mjs)

The rebuilt Windows MyGo package passed that expanded navigation smoke. Grid moved from 0 to 3007.199951 CSS pixels against a rounded extent of 3007; Filmstrip moved from 0 to 1881.599976 against 1882. Independent PNG decoding found the first and last generated thumbnail bands at their respective positions. The native watch observed the actual movement while reads, no-op writes and stale selection rejection added no revision. Hidden targets, default Detail compatibility, selection and edit retention, 36 unchanged generated source files and the two original fixtures passed. The existing trusted keyboard, fullscreen and preference restart checks also passed. This is Windows WebView2 evidence; packaged Linux and macOS coverage remains separate.
