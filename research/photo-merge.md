# Photo merge evidence and implementation choice

Reviewed 2026-11-05. The target remains installed Lightroom 9.4, with the SHA-256 and REA resource identity recorded in [the Lightroom report](lightroom.md) and [catalog follow-up](catalog-organization.md). This investigation does not execute Lightroom or recover its pixel implementation.

Read-only inspection of `Resources/zh_cn/TranslatedStrings.txt` found `AgLibrary/Menu/Library/PhotoMerge/Progress` entries for HDR, panorama and preparation at lines 1592–1599, and `AgPhotoMerge/Merge/Error` entries for incompatible inputs, insufficient metadata, invalid warp, insufficient matches and camera-motion estimation at lines 1814–1821. These are shipped strings, not evidence that those runtime paths executed. Adobe's bytes are not copied into this repository.

[Adobe's desktop merge guide](https://helpx.adobe.com/lightroom/desktop/edit-photos/hdr-panorama.html) documents exposure-bracketed HDR, optional alignment/deghosting, overlapping panoramas, and projection choices. It describes newly generated DNG results. That documentation establishes product workflows; it does not disclose Adobe's registration or radiance pipeline. OpenLR's PNG plus Radiance RGBE output and perspective-only panorama are explicit independent choices.

Context7 resolved `/techstark/opencv-js` and supplied current initialization, perspective-transform, and runtime API documentation. The package's [own repository](https://github.com/TechStark/opencv-js) and [API surface](https://github.com/TechStark/opencv-js/blob/main/doc/cvKeys.json) corroborate runtime initialization and the needed ORB, matching, homography and warp operations. Runtime inspection of the installed, pinned `@techstark/opencv-js` 5.0.0-release.1 confirmed those APIs and OpenCV 5.0.0. The artifact, licenses, build information, and hashes are retained under `web/vendor/opencv/`.

OpenLR uses real feature registration and projective resampling. For HDR it uses known-response exposure-calibrated linear radiance recovery, rather than claiming to solve an unknown camera response or reproduce Adobe. Rendered sRGB conversion follows the transfer relationship described in [W3C CSS Color 4](https://www.w3.org/TR/css-color-4/#color-conversion-code). The HDR file follows the shared-exponent picture format described in [Radiance's file-format reference](https://radsite.lbl.gov/radiance/refer/filefmts.pdf). Mathematical relationships were implemented as project code; documentation text or upstream application algorithms were not copied.

Feasibility was established with actual OpenCV WASM, generated displaced exposure brackets, overlapping textured views, independent RGBE decoding, generated sensor DNGs, and browser UI/worker/fallback tests. The [implementation guide](../docs/photo-merge.md) records thresholds, commands, validated metrics, and unresolved quality limits. No claims are made about Adobe-equivalent deghosting, spherical stitching, camera bundle adjustment, panoramic HDR grouping, or photographic benchmark performance.
