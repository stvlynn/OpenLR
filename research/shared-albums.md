# Shared album research

Reviewed 2026-11-05. Adobe's [desktop sharing documentation](https://helpx.adobe.com/lightroom-cc/using/save-share-photos.html) describes starting from an album or photo selection, creating a shareable link, controlling access, and permitting comments/likes. It also distinguishes view, contribute, and editing roles, and settings for downloads and metadata. Adobe's [web review documentation](https://helpx.adobe.com/lightroom/web/share-your-work/share-and-invite/share-photos-and-albums-for-review.html) describes album review through share links and invitations. This is published documentation evidence; no Adobe authenticated service or runtime was accessed for this feature.

OpenLR implements the requested view-and-review workflow with an independently deployable, original AGPL server and a small browser gallery. Publication comes from the existing album dispatcher and existing image renderer. The viewer does not contain another photo editor. Access uses a per-album secret capability link that can be revoked, rather than Adobe accounts or email invitation roles. Reviewer names are self-declared; likes are deduplicated using the viewer browser's local identity. This is not authenticated person identity or an Adobe-compatible collaboration protocol.

Only edited JPEG previews and filenames are sent when publishing. Source RAW files, catalog edit recipes, location metadata, credentials and private photographs were not uploaded by validation. The real end-to-end test used generated photos and loopback addresses only. It opened the actual gallery in Chrome, submitted a comment and like, read both through the native GUI/CLI, and verified missing-key and revoked-link denial. See [deployment and workflow](../docs/shared-albums.md).
