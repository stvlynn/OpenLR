# Dehaze: bounded research and implementation contract

Reviewed 2026-11-05. This proposal is independent of Adobe's algorithm. No production code or third-party implementation was copied. The [completion audit](completion-audit.md) identifies the missing control; the [Lightroom ledger](lightroom.md) records L1 Dehaze parameter evidence and the root agent's bounded UI observations. A parameter name and visible slider do not establish its rendering mathematics.

## Primary sources

The authors' [dark-channel prior project](https://people.csail.mit.edu/kaiming/cvpr09/index.html) and [CVPR 2009 paper](https://people.csail.mit.edu/kaiming/publications/cvpr09.pdf) motivate estimating transmission from local dark pixels under an atmospheric-scattering model. Their [guided filtering paper](https://people.csail.mit.edu/kaiming/publications/eccv10guidedfilter.pdf) supplies a local linear, edge-aware refinement with linear-time box-sum implementations. These are priors, not guarantees about arbitrary photographs.

Context7 resolved OpenCV, but `/opencv/opencv` initially returned adjacent edge-filter material. A follow-up against `/websites/opencv` returned the actual [guidedFilter documentation](https://docs.opencv.org/5.0/extra_modules/ximgproc_filters.html): distinct guidance and input images, radius, regularization epsilon and optional subsampling. The pinned [OpenCV contrib 4.13.0 API header](https://github.com/opencv/opencv_contrib/blob/4.13.0/modules/ximgproc/include/opencv2/ximgproc/edge_filter.hpp) is an inspectable primary GitHub reference. No OpenCV dependency, source, binary or license declaration is imported. The proposed independent equations below use these mathematical ideas within OpenLR's existing linear-float contract.

## Executed ablation

Run `node research/dehaze-ablation.mjs`. Windows Node v24.9.0 executed this tracked, independently authored generated-data experiment. Output `.workspace/dehaze-ablation.json` is ignored. It is a numerical research implementation, not another production renderer.

A 64 × 32 linear RGB scene contains smooth colored structure and sparse dark anchors every third row/column. Four top rows equal known airlight A=(.85,.9,1). Observed samples follow `I=J*t+A*(1-t)`, with t=.35 left and .8 right. All candidates estimate A, and all recovered the generating airlight within floating-point precision. Dark patch radius is 2; refinement radius is 3; guided epsilon is 1e-4. MSE excludes the top four airlight rows; edge MSE uses the seven columns around the depth boundary. Input MSE is .09448463.

| Transmission estimate     | Recovered MSE |  Edge MSE | Same algorithm on clear scene, MSE |
| ------------------------- | ------------: | --------: | ---------------------------------: |
| Per-pixel dark ratio      |     .01993386 | .02760984 |                          .02954029 |
| Local patch minimum       |     .00476822 | .03082982 |                             <1e-32 |
| Patch + box smoothing     |     .00527620 | .02913376 |                          .00060250 |
| Patch + guided refinement |     .00468984 | .02273639 |                            5.53e-7 |

Select patch dark-channel estimation plus guided refinement: it has the lowest whole-scene and boundary error in this fixture, avoids the per-pixel clear-scene distortion, and improves on ordinary smoothing. Guided refinement is not halo-free: boundary error remains measurable. The fixture deliberately satisfies the dark-channel prior; this is not a broad natural-image benchmark.

Additional actual checks: zero amount is bit-exact identity; negative -100 reduces within-region contrast to .4 of the input; alpha is unchanged; transparent output samples are unchanged; applying the frozen estimated map to signed/HDR components up to 3e20 produces finite, unclipped values. A uniform clear .7 field remains .7, but a deliberately prior-violating clear scene with .7/.9 bright objects beneath a .95 strip is distorted severely at +100: output .11667/.45 and MSE .25863039. This negative result is retained: large bright objects, snow and sky are an ambiguity of this estimator, with severe overcorrection possible at the explicitly requested full strength. Do not claim automatic haze detection, universal improvement or accurate recovered depth. User-controlled strength is essential. Estimator contamination by transparency and full-resolution resource behavior still require implementation tests; the stress fixture tests reconstruction with a frozen map, not transparent-aware map estimation.

## Domain and equations

Add scalar `Dehaze` in [-100,100], finite numeric, default/absent 0, alongside the existing Effects controls. Use the normal edit command, history, snapshots, presets and selective-copy group. No second recipe or paste path. Nonzero values are edited; zero remains neutral. Exact zero must return before allocation, analysis or transfer-function conversion so existing recipe pixels stay identical.

The shared domain operation consumes straight-alpha linear RGB. Estimate only a bounded analysis proxy; reconstruct from the original unbounded values. Positive processing:

1. Build per-component analysis proxy `clamp(RGB,0,1)`. Ignore alpha-zero samples in all statistics. Positive-alpha samples contribute alpha weights to averages; hidden RGB must never alter a neighbor's result. If no visible samples exist, return the input unchanged.
2. Compute the minimum across RGB and a square patch. For empty patches, record no evidence rather than treating transparency as black. Initial production radius proposal is `max(2,round(.007*min(width,height)))`; this is a product parameter pending image acceptance, not a literature-derived constant.
3. Among the top 0.1% of valid dark-channel values (at least one), choose the sample with greatest proxy luminance, deterministic raster-order tie breaking. Its RGB supplies A; floor each channel at 1e-4 to avoid division by zero. An exactly black visible proxy has zero haze evidence and transmission 1; no near-black confidence threshold or automatic haze-detection gate is proposed. Positive-alpha candidate selection must be deterministic and must not admit alpha-zero candidates. The experiment uses a full sort for clarity; production should use selection/histograms instead.
4. From the original input's nonnegative RGB divided by A, compute the local minimum ratio; bound only the resulting evidence to [0,1]. Define coarse transmission `1-.95*ratio`. Values above display white do not get clipped during reconstruction. The .95 factor retains some haze and is an explicit chosen parameter.
5. Refine transmission using scalar proxy luminance as guide. Within each clipped-border window, calculate alpha-weighted means, variance and covariance; `a=cov(guide,t)/(max(var(guide),0)+1e-4)`, `b=mean(t)-a*mean(guide)`. Average valid a/b with matching support, then evaluate `mean(a)*guide+mean(b)`. Use no-data fallbacks of transmission 1. Suggested refinement radius `max(3,round(.02*min(width,height)))` preserves the experiment's minimum support; validate it on real exported images.
6. Bound the final transmission map to [.1,1]. With `u=Dehaze/100`, use `T=1-u*(1-t)` and reconstruct each RGB component as `A+(I-A)/T`. This guarantees identity at u=0, a bounded gain of at most 10, and gradual strength. Do not clamp RGB or change alpha. Alpha-zero output retains its original hidden components. Intermediate precision and final finite-value validation still matter for values near floating-point limits.

For negative amounts, use the same estimated airlight but skip transmission refinement: `f=.6*(-Dehaze/100)`, `out=(1-f)*I+f*A`. This deliberately adds a uniform airlight veil, reduces contrast continuously, and keeps a minimum .4 contribution from the original at -100. It is not an inverse of arbitrary positive dehaze because positive transmission is spatially varying. No depth estimate is claimed for added haze. Use a neutral A=(1,1,1) only when every visible proxy component is exactly zero, allowing negative haze to lift black; all-transparent images remain unchanged. This fallback is specific to haze synthesis and must not affect positive processing.

## Pipeline, precision and resources

Place dehaze after existing source corrections/optics but before global tone, curves, mixer and grading: haze estimation should not interpret a creative color grade as atmospheric light. For preview/export agreement, use the same source-coordinate analysis frame and cache key, independent of the requested preview edge. Apply its map before crop/resize, so view-size and cropping do not silently change global A or the local spatial footprint. Existing legacy source-stage downsampling must be inspected during integration; computing statistics from whatever preview-size canvas happens to be available would violate this contract. A persistent source-resolution map or a fixed canonical analysis pyramid with properly specified reconstruction are alternatives; start with exact source-resolution O(N) analysis and measure actual memory before introducing an approximation.

Both process versions call one domain implementation. Legacy decodes current source samples to linear and returns an encoded byte result only at its existing adapter boundary. Linear passes float data directly. Neither path modifies cached originals, hidden alpha, or output color-space ownership. No-op bypass preserves legacy behavior exactly. Dehaze must be recognized in rendering fast paths and copy selection through the existing controls owner.

Use separable sliding minima with a monotonic deque and separable running box sums, giving O(N) time independent of radius. Guided filtering requires several scalar planes; reuse buffers, keep guide/transmission/coefficients in Float32 where verified, use Float64 accumulation, and account for total peak memory. Eight Float32 scalar planes alone cost 32N bytes (about 768 MB at 24 megapixels), before image buffers. This is a resource cost to reduce through buffer reuse or tiled processing, not a new arbitrary photo-size rejection. Tiled exact processing needs overlapping support through both guided-filter box passes, plus the dark-minimum radius; airlight selection stays global. A worker belongs behind the existing adapter and must carry source/edit revision, discard stale results, and report allocation/processing failures visibly. No speculative runtime performance claim follows from this small experiment.

## Acceptance required before shipping

Test known-airlight recovery, depth discontinuities, flat/bright/saturated scenes, tiny images, all-black/all-transparent images and alpha-zero contamination. Verify signed/HDR reconstruction, finite outputs, no-op exactness, negative haze, monotonic strength, unchanged originals/alpha and independent slider histories. Compare actual preview and decoded exports at different dimensions/crops, verify both processing versions and persisted recipes, and measure representative large-image latency and peak memory. Preserve the negative bright-object result in documentation instead of claiming the prior always distinguishes a bright surface from haze. Native controls, keyboard interaction and end-to-end export still require real app acceptance.
