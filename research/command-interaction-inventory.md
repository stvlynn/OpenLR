# Remaining OpenLR GUI / CLI interaction audit

Source baseline `ca1299b`; findings below precede the repairs recorded later in this document. This inventory covers interaction owners, including native menu routing, and uses the existing browser/native test sources as evidence maps. A listed existing test is not a new execution. The Chrome reproductions and source CLI / packaged Windows host video checks below were executed for this audit.

## Confirmed at the baseline, in priority order

1. **A White Balance click can edit a different photo.** The canvas handler calculates original coordinates against the current bitmap and calls unguarded `white-balance` (web/app.js:2323–2333); the queue resolves the active asset later and commits there (web/app.js:2063–2069). Real Chrome held the real thumbnail encode for an edit on warm.png, queued selection of cool.png, then delivered a trusted click on the still-visible warm.png canvas. Cool.png acquired `{Temperature:100,Tint:-69}`, while warm.png retained only the preceding Exposure:-1. The original-coordinate command is semantically useful; a guarded display-coordinate operation can share the GUI mapping and existing white balance commit. Verify real GUI and actual CLI with distinct warm/cool swatches, crop/rotation/flip/optics, stale revision rejection, undo/reopen and actual preview/export pixels. .workspace/remaining-audit.mjs reproduces the old code.
2. **Losing crop pointer capture strands the active drag.** CropSurface listens for pointer up/cancel but not lostpointercapture (web/crop-surface.js:10–25); dispatcher refuses crop-drag/crop-nudge while drag is set (web/app.js:1392–1405). Real Chrome acquired and released actual stage pointer capture, moved/up outside the stage, then observed `Finish dragging the crop rectangle first` from crop-nudge. Verify cancellation restores the pre-drag crop and subsequent mouse/actual CLI work, with displayed draft/actual exported pixels and unchanged recipe until Done. .workspace/remaining-audit.mjs reproduces.
3. **Photos sidebar explicit state and panel observation.** `panel` toggles Photos regardless of `args.open` (web/app.js:1363–1367); Chrome observed open:true hides, open:false shows. Inspector `<summary>` disclosures use browser defaults (web/index.html and mounted panels) and do not update a readable panel state in snapshot (web/app.js:644–694). Catalog Filters and Photo menu disclosures also have no equivalent in panel's aside-only lookup (web/organization-ui.js:53, web/stacks.js:70). This concerns navigation/disclosure state, independent of filter/action commands. Verify actual idempotent GUI/CLI open/close, live change notification, and independent screenshot/DOM visibility. .workspace/remaining-audit.mjs reproduces explicit sidebar state inversion.

## Panel event research — 2026-11-06

The follow-up assembled DOM contains 20 `details` nodes (16 inspector, two toolbar, two Photos sidebar), plus the Photos visibility control. Its exact names are available from the mounted first summaries; Filters later adds a count to its label. Baseline Chrome 156 inspection confirmed that mouse and Enter changed Filters without a workspace event, while the global Space shortcut consumed summary activation. These are OpenLR runtime observations, not Lightroom behavior claims.

Context7's `/mdn/content` documentation for [details](https://github.com/mdn/content/blob/main/files/en-us/web/html/reference/elements/details/index.md) and [toggle](https://github.com/mdn/content/blob/main/files/en-us/web/api/htmlelement/toggle_event/index.md) confirms that native state changes precede `toggle`, rapid changes may coalesce, and a focused summary supports Space. The [HTML summary activation rules](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-summary-element) are the browser contract. A separate real-Chrome probe observed one trusted cancelable click for mouse, Enter and Space; preventing that click's default prevented the native state mutation.

An isolated Chrome 156.0.8078.80 comparison then issued two synchronous `summary.click()` calls. These were synthetic activations to control task ordering, not physical input or production end-to-end acceptance. All candidates ended closed. Native-only supplied no application notifications; observing `toggle` supplied just `[false]`; intercepting clicks and queuing the same state transition supplied `[true,false]` and two command requests. The last approach preserves each queued operation without feeding programmatic `open` changes back into another command. This experiment measures event semantics, not rendering speed. Reproduce it with `node tests/panel-event-ablation.mjs`; the recorded output is also retained in ignored `.workspace/panel-event-ablation.log`.

The implementation uses actual DOM `open`/`hidden` as the state owner, stable names captured once after mounts, and the existing queue and watch transport. No new state store, package or imported competitor code is needed. `tests/panel-state.test.js` independently checks the 21-key inventory, actual controls, explicit state and queued toggles, trusted inputs, one workspace event per activation, dynamic labels and automatic menu closure. Existing local-gesture tests preserve cancellation when Masks closes. The focused combined suite passed 21/21 on Windows / Chrome 156. Full and native completion are recorded separately in [acceptance](../docs/acceptance.md); the event comparison alone does not prove them.
