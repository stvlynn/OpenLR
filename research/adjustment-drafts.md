# Shared adjustment drafts

The existing slider input handler paints a temporary recipe and the change handler commits through `edit`. Point curves and grading use their own pointer state, then call `editPreview` to derive a temporary recipe and `curve-set` or `grading-set` to commit. All three ultimately render through `paintStage`. The GUI can show a candidate without writing the catalog, and the existing histogram workflow observes different display and committed bins during a held slider draft. The CLI can read those bins or capture the workspace, while its `preview` command renders the committed recipe or comparison image. The crop tool already exposes a shared session draft through the dispatcher. ## Design comparison

The alternatives below compare the command contracts. Only the optional draft mode was implemented for the runtime comparisons.

| Candidate | Draft operation, result and lifetime |
| --- | --- |
| Override arguments on image export | Can render trial pixels. It does not stage the real editor surface, share the GUI gesture owner or supply a cancel/commit lifetime. |
| Dedicated draft command with nested edit envelope | Can stage and report the real surface. Its nested command allowlist, nested argument shape and discovery duplicate parts of the existing typed edit commands. |
| Optional draft mode on existing typed edits | Keeps the existing scalar, point and grading argument contracts and validation. One transient owner handles painting, readback, cancellation and commit. |

The selected design adds `draft: true` to `edit` for the existing numeric adjustments, `curve-set` and `grading-set`. Each staged update returns a new opaque ID. `state` and `watch` report the active `adjustmentDraft`, including the selected photo, typed change and publication status. `draft-commit` and `draft-cancel` address that ID. `preview --source draft --draftId ID` reads the published edited pane as PNG at the actual viewport canvas dimensions. The default image preview and exports retain their existing recipe contracts. A new request can supersede an older draft. An outdated ID cannot cancel, commit or read the newer one.

The dispatcher admits a valid draft before its scheduled render finishes. This keeps a new selection, cancel or update from waiting behind a large draft render. Only the latest owner can publish its result. The existing renderer and worker preparation remain shared, including cancellation and ownership checks for asset, source, recipe and view. Reading a ready draft uses the existing published canvas and checks its identity again after PNG encoding. Comparison and clipping follow the displayed edited pane. The native screenshot still captures the full workspace. [Animation-frame cancellation](https://github.com/mdn/content/blob/main/files/en-us/web/api/window/cancelanimationframe/index.md) · [AbortSignal](https://github.com/mdn/content/blob/main/files/en-us/web/api/abortsignal/throwifaborted/index.md)

The basic slider, tone-curve graph and grading wheels/ranges submit their transient changes through the shared draft dispatcher. The controls retain their pointer and focused-input behavior. Canceling or replacing the token from the CLI also ends its originating GUI gesture. A later pointer release cannot save the canceled value. The existing scalar validation, curve setter, grading setter and save/history owners apply a commit once. Targeted curve and grading guards remain in their existing commit paths. Drafts stay outside catalog records, copy/export state and undo history until a successful commit.

## Runtime comparison

The initial focused Windows Chrome 156.0.8078.80 run passed 21 tests. The draft PNG matched every published stage pixel, and sampled curve and grading pixels matched after commit in both processing versions. Draft reads retained the prior saved recipe and history until commit. Cancel restored the committed image. Trusted basic slider, curve and grading gestures exposed the same draft state and PNG. Canceling each held gesture through the command prevented the later pointer release from saving it. [Draft workflow tests](../tests/adjustment-drafts.test.js)

Separate controlled cases delayed real worker results and real canvas PNG completion. A newer draft published before a held older read completed. The older read rejected, and delayed work did not replace the newer canvas after supersession, cancel or selection. A forced rendering failure reported its status while preserving the previous canvas, and a new request could render afterward. [Ownership and failure tests](../tests/adjustment-draft-races.test.js)

A queue-order comparison held an ordinary command while the CLI queued a cancel or replacement, then released the GUI pointer before the queue resumed. In the first implementation all six combinations wrote the released gesture anyway. Carrying the originating gesture into its typed commit lets the dispatcher observe cancellation when that commit reaches the queue. All six combinations then retained the saved recipe, and each replacement token remained current. The expanded race file passed all four tests on Windows Chrome. [Queued pointer regression](../tests/adjustment-draft-races.test.js)

The final combined draft files passed 10/10 tests, including a real IndexedDB write failure that preserved the stored recipe, restored displayed pixels and added no undo entry. Staging from Show original also clears the comparison button's pressed state. The first trusted grading test omitted opening its panel; inspecting the actual panel/focus identified that test setup error, which was corrected without weakening the assertion.

A new Windows MyGo/WebView2 package passed `native-adjustment-smoke.mjs` and the existing `native-smoke.mjs`. The dedicated test independently decoded every Exposure sample, checked a workspace screenshot patch and both histogram modes, sampled curve/grading output, and verified local sidecar bytes, two-step undo and originals. Actual process restart retained the committed Exposure and removed the abandoned draft. The generated source RGB `[48,76,112]` became `[69,106,154]` at Exposure 1; the baseline Exposure .25 remained `[53,83,121]` until commit. These are Windows package observations; the ordinary native suite now includes the same test for other platforms. The installer was built, not executed. Ignored logs are `.workspace/adjustment-final-targeted.log`, `.workspace/adjustment-build-final.log`, `.workspace/adjustment-native.log` and `.workspace/adjustment-native-main.log`.
