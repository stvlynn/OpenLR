# Native audio sample origin

The macOS AudioToolbox probe returned 10,440 samples from an Opus stream containing 10,560 coded frames. Against raw Chrome PCM, the waveform matched at a lag of 120 samples with relative RMS error below `1e-7` on ARM and Intel. The tested stream began in CELT-only mode. Supplying the native cookie, omitting it, or supplying either `OpusHead` variant left the result unchanged. Both runners rejected the prime method query and change, and decoder prime info reported zero. The converter interface returns PCM and counts without a timestamp for the first returned sample. [Native probe results](native-video.md#opus-decoder-timing-ablation) · [Apple converter API](https://developer.apple.com/documentation/audiotoolbox/encoding-and-decoding-audio)

RFC 7845 describes 120 samples of initial overlap for a first CELT frame and separate latency in SILK. Its pre-skip rule describes samples to decode and discard according to the stream header. It does not identify an AudioToolbox output offset for SILK, hybrid, or a mode transition. WebKit's Cocoa track path explicitly clears Opus pre-skip from its decoder configuration and leaves that timing to its caller. The published code offers no general rule for the observed AudioToolbox omission. Equal packet and PCM counts establish length, while a count deficit alone cannot locate missing samples on the timeline. [Opus pre-skip and seek preroll](https://www.rfc-editor.org/rfc/rfc7845.html#section-4.2) · [WebKit Cocoa decoder](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/platform/audio/cocoa/AudioDecoderCocoa.cpp#L130-L167)

## Packet decoder evidence

The pinned MediaBunny audio sink delegates compressed Opus to WebCodecs or a registered custom decoder. The standalone adapter in `web/opus-decoder.js` uses the vendored `libopus-wasm` runtime. Its stateful `decodeFloat` method returns full decoded packet PCM. The reference API reports decoded samples per channel and supports up to 120 ms per packet. [MediaBunny 1.65.1 sink](https://github.com/Vanilagy/mediabunny/blob/v1.65.1/src/media-sink.ts) · [Reference decoder API](https://opus-codec.org/docs/opus_api-1.5/group__opus__decoder.html)

System libopus 1.4 on WSL Ubuntu generated and independently decoded the 48 kHz test packets. The generator used the upstream private mode control solely to select fixture modes and verified each actual TOC. Chrome 156.0.8078.80 decoded the same packets through `libopus-wasm` 0.4.1 and its libopus 1.6.1 runtime over loopback. The page was not cross-origin isolated. Mono and stereo each used six configurations.

Every decoded packet matched its TOC duration, and the PCM comparisons used the same sample indices with no shift. After feeding 80 ms of real packet preroll, the four fresh interior starts matched the corresponding continuous decode with relative RMS error below `7.9e-8`. Cold module import plus first decoder creation took approximately 25 and 44 ms in two local runs. In the final run, warm decode plus handle creation and disposal took 0.32–1.44 ms for 0.20–0.48 seconds of audio, averaged over 50 iterations per configuration. These are local Chrome decoder measurements. The generated packets, scripts and report remain under ignored `.workspace/audio-origin/`. [Upstream fixture mode control](https://github.com/xiph/opus/blob/v1.6.1/src/opus_private.h#L134-L155)

`node --test tests/opus-decoder.test.js` exercises the vendored adapter with the compact generated fixtures. It verifies raw origin, packet sizes, mode transitions, fresh decoder preroll, signed gain, returned PCM ownership and close behavior. WebKitGTK 2.52.6 MiniBrowser on WSL Ubuntu also loaded the same runtime modules and decoded the three fixtures over loopback without cross-origin isolation. ## Export integration boundary

Use one stateful reference decoder per Opus track in the desktop fallback and AudioToolbox for AAC decoding and Opus/AAC encoding. The tested wrapper can handle mapping-family-zero mono and stereo at 48 kHz. Carry the Opus header's output gain, use its original sample rate as informational metadata, and surface unsupported channel mapping. Load the WASM only when the fallback needs Opus input. The AudioToolbox Opus decoder remains useful for platform diagnostics. The export path needs only one Opus decoder. [Opus identification header](https://www.rfc-editor.org/rfc/rfc7845.html#section-5.1)

Use the demuxed packet timestamps to place each run of contiguous packets, and advance that run by the integer TOC frame count. Keep a single decoder across packets and mode changes. At a discontinuity or interior restart, open a fresh decoder and feed actual preceding packets through the track's seek preroll, with 80 ms as the Opus reference. Determine whether that run starts with the true first track packet. Apply stream pre-skip at the track start and apply the container's signed padding or presentation range once. Intersect the resulting audible samples with the requested half-open trim, then rebase audio and video against the same trim origin. Use bounded PCM chunks throughout. [Opus seeking](https://www.rfc-editor.org/rfc/rfc7845.html#section-4.6) · [Matroska timing](https://www.rfc-editor.org/rfc/rfc9559.html#name-discardpadding-element)

The AAC bridge should wrap the input track's exact `AudioSpecificConfig` in a length-checked MPEG-4 elementary stream descriptor for `AudioConverterDecompressionMagicCookie`. Apple documents `AudioFormatGetProperty` for deriving the stream description from codec configuration. WebKit follows this approach and extracts the exact `DecoderSpecificInfo` bytes from the encoder cookie for its outgoing AAC configuration. Use the negotiated format and packet timing rather than a fixture's rate, sample count, or priming. The existing native round trip proves the generated AAC-LC cases using their encoder cookies. An independent browser-produced AAC input still needs to exercise the bridge's wrapping path. [Apple AudioFormat properties](https://developer.apple.com/documentation/audiotoolbox/1577853-audio-format-property-identifier) · [WebKit AAC descriptors](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/platform/audio/cocoa/AudioUtilitiesCocoa.cpp#L54-L135)

The next packaged macOS test should exercise the real fallback with an interior packet-unaligned trim. Decode its output independently and verify the first and last audible samples, channel signal, initial track offset, A/V alignment and original bytes for both WebM/Opus and MP4/AAC. Run the mixed Opus modes and an externally encoded AAC-LC case on both architectures. This also establishes WASM loading inside the packaged WKWebView.
