# Photos and Inspector viewport parity

Photos and Inspector are separate browser scrollports. On Windows Chrome 156.0.8078.80 at baseline `af5e06d`, trusted wheel input moved the Photos sidebar from 0 to 730 CSS pixels and changed the visible generated album names from 00–07 to 15–27. Selecting album 31 through `scope` while the sidebar was at the top kept it there. The **Masks & local repair** panel command scrolled Inspector to 1199 CSS pixels, bringing the section into view. Wheel input moved it to 1539 and revealed **Create color range**, **Create luminance range** and the composite mask controls. Reopening that section retained the interior offset. Neither scroll woke `watch`, and the viewport schema only accepted Detail, Grid and Filmstrip. [Earlier catalog viewport work](catalog-viewport.md)

The shared `viewport` command now also resolves `photos` and `inspector` to the actual sidebar elements. Full and summary state return their live offsets and dimensions under `panelViewports`. Visibility follows the same DOM `hidden` state as the workspace, with slideshow hiding both panels. Empty Photos remains readable. Opening a named panel and moving to an absolute sidebar offset serve different purposes. Scope selection and panel opening retain their existing behavior. [CLI contract](../docs/agent-cli.md#shared-session-transport)

Both targets reuse the existing instant scroll write, clamping and DOM scroll event. CSSOM View specifies that browser input and API writes enqueue the same element scroll event. The MDN references checked through Context7 distinguish fractional offsets from rounded client and content dimensions. The dispatcher reads the actual offset after moving and relies on the browser's event instead of sending a second notification. [CSSOM View scroll events](https://drafts.csswg.org/cssom-view/#scrolling-events) · [MDN scrollHeight](https://github.com/mdn/content/blob/main/files/en-us/web/api/element/scrollheight/index.md)

The Windows Chrome test verifies that trusted wheel input and the shared command reach identical offsets and compares their decoded screenshot regions. It covers a tall Inspector section, empty Photos, hidden panels, slideshow, deleted photos, read and no-op observation, and queued scope and selection changes behind a held catalog write. It also checks the selected photo's recipe and original bytes. Native workspace capture and native broker observation are separate checks. [Browser regression](../tests/panel-viewport.test.js)

`node --test --test-concurrency=2 tests/panel-viewport.test.js tests/catalog-viewport.test.js tests/viewport.test.js tests/panel-state.test.js tests/agent-cli.test.js` passed 13/13 on Windows Chrome 156.0.8078.80. The first combined run passed the new test and found that the existing disclosure test counted Playwright's scroll to an offscreen summary as part of the click. The disclosure check now brings the control into view and waits for that scroll event before requiring one event for activation. The viewport test observes scroll events separately.
