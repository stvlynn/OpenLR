# DNG export investigation

Reviewed 2026-11-05. Adobe's [DNG resource page](https://helpx.adobe.com/camera-raw/desktop/dng-and-file-formats/digital-negative.html) links the official [DNG 1.7.1 specification](https://helpx.adobe.com/content/dam/help/en/photoshop/pdf/DNG_Spec_1_7_1_0.pdf). Relevant sections are the 64-bit container layout (pages 18–19), raw photometric interpretation and orientation (pages 22–23), black/white levels (pages 28–29), color matrix (pages 32–33), neutral balance (page 36), and original filename (page 42). The specification permits LinearRaw for demosaiced data and defines ColorMatrix as XYZ-to-reference-camera coordinates. These facts establish the container contract, not Adobe's conversion algorithm.

Context7 identified `/photopea/utif.js` and described newer upstream TIFF APIs, including 16-bit paths. Direct inspection of the locked UTIF **3.1.0** package showed that its installed `encodeImage` hard-codes four 8-bit channels. That existing helper was therefore unsuitable for authentic RAW output. OpenLR's writer uses the shared LGPL LibRaw reader for true 16-bit linear samples and writes the documented container directly. No new DNG SDK dependency, SDK license assumption, or preview-to-RAW conversion was introduced.

The input pixel space is camera-white-balanced linear sRGB, so the synthetic output camera model uses the inverse sRGB-D65 XYZ matrix and a neutral of one. This is different from copying a source camera's CFA color matrix onto already transformed RGB. An independent metadata parser checks the emitted tags, and LibRaw reopens the file to verify resulting sample values and oriented dimensions.

Validation includes the project's generated RGGB sensor DNG and a genuine non-DNG Canon PowerShot G1 CRW from [raw.pixls.us](https://raw.pixls.us/), explicitly licensed CC0-1.0 in sample 2073's repository row. Its provenance and SHA-256 are retained in `tests/fixtures/raw/canon-powershot-g1.json`. Both paths preserve source bytes. The converted file retains sub-eight-bit sample differences and returns through the real RAW decoder with approximately one-level maximum 16-bit error. These are observed OpenLR tests, not results from Adobe's SDK validator or a broad camera-format compatibility study.
